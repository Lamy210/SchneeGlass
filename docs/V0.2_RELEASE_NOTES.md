# SchneeGlass v0.2.0 Release Notes — Draft

> Status: v0.2.0 development / ad-hoc candidate preparation. Developer ID signing and Apple notarization will not be used ([ADR-0011](adr/0011-adhoc-distribution-without-developer-id.md)). This is not yet a published v0.2.0 Release.

SchneeGlass v0.2.0 focuses on making each Desktop Glass easier to place, recover, and use every day while preserving the non-destructive file-safety contract established in v0.1.x.

Project metadata:

- Version: `0.2.0`
- Build: `3`
- Minimum macOS: `15.0`

## Highlights

### Window placement and control

- Desktop Glass can be dragged from non-interactive background/header regions.
- Position Lock prevents accidental dragging without disabling resize or file interaction.
- Reachability constraints keep a usable part of a Glass on-screen.
- Reset Glass Positions remains an explicit rescue path even for locked Glasses.
- Keep on Top is available per Glass.
- Show on All Spaces can be changed per Glass.
- Snap presets place a Glass at Top Left / Top Right / Bottom Left / Bottom Right / Center of the current display.
- Opacity presets: 100% / 90% / 80% / 70%.

### Glass management

- Unavailable Glasses can reconnect to their original folder without creating a new Glass.
- Reconnect preserves the Glass ID, placement, and Window UX preferences.
- Connected folders can be revealed in Finder.
- Glass display names can be renamed without renaming the source folder.

### File presentation

- Compact File Tiles provide a denser per-Glass grid.
- Sort Displayed Files supports:
  - Name
  - Modified (newest first)
  - Size (largest first)
- Folders First can group real directories before other displayed items while preserving the selected sort inside each group.

File sorting is presentation-only. It does not mutate the folder snapshot, Glass configuration, or source files.

## File-safety contract

v0.2 keeps the existing non-destructive boundary:

```text
User-owned source Move      = 0
User-owned source Rename    = 0
User-owned source Delete    = 0
Silent overwrite            = 0
Unknown partial auto-delete = 0
```

Regular-file Drag & Drop remains copy-only and uses the existing staging / recovery / ownership-proof flow.

Window and presentation preferences are stored separately from folder identity and copy authority. They never become filesystem mutation authority.

## Display boundaries

- Folder snapshots remain one level deep.
- Hidden files are still skipped during snapshot enumeration.
- A Glass displays at most 500 loaded items.
- Sort Displayed Files reorders the loaded snapshot only. It does not rescan the whole folder to select a global newest/largest top 500.
- Folders First promotes only `FileKind.directory`; package, alias, symbolic-link, and unsupported kinds keep their existing semantics.

## Release validation

The repository now contains three distinct candidate paths:

1. **Unsigned Release Candidate**
   - build/package integrity validation only
   - no code signature

2. **Ad-Hoc Release Candidate**
   - ad-hoc code signature
   - Hardened Runtime
   - App Sandbox
   - user-selected read/write entitlement
   - SHA-256 checked Actions artifact
   - testing only; never published automatically

3. **Historical Production Release Candidate — not used**
   - Legacy Developer ID Application signing / Apple notarization / stapling
   - strict `RELEASE_EVIDENCE.txt`
   - Retained for historical validation; **do not dispatch** as the current distribution path.

The current ad-hoc workflow creates a **test artifact**, not a GitHub Release. It must never be misrepresented as Apple-notarized.
