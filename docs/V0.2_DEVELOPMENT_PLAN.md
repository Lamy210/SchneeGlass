# SchneeGlass v0.2 Development Plan

## 1. Goal

v0.2は、v0.1.xで確立したFile Safety / Recovery / non-destructive contractを維持したまま、Desktop Glassを日常利用しやすいWindow UXへ進化させます。

v0.1.1のad-hoc signed GitHub Release公開後も、Developer ID signing / notarization / immutable production publicationはIssue #33の独立したrelease-operations trackとして継続します。v0.2の通常機能開発は、そのcredential準備だけを理由に停止しません。

## 2. Invariants

v0.2でも次を維持します。

- user-owned source fileのMove / Rename / Deleteを自動実行しない
- silent overwriteを行わない
- filesystemをSource of Truthとする
- Security-scoped accessのacquire / releaseをbalanceする
- unknown / ambiguous recovery stateを自動削除しない
- PresentationからConcrete FileSystem / Persistence Adapterへ直接依存しない
- private macOS API / Accessibility Permissionを導入しない
- Window UX preferenceをfolder identity / copy authorityとして使用しない

## 3. Phase 1 — Window UX Foundation

### V02-001 — Movable Desktop Glass

Status: **MERGED**

- Desktop Glassのbackground/header areaから移動可能にする
- existing `windowDidMove` placement persistenceを再利用する
- file grid / context menu / scrollingとの競合をManual QAする
- multi-display placement recoveryを維持する

Tracking: PR #318

### V02-002 — Persistent Position Lock

Status: **MERGED**

- Glass単位でPosition Lock / Unlock
- Lock中はuser dragだけを禁止
- resize / file interaction / drop / menuは維持
- lock状態を再起動後も維持
- Glass configuration schemaとは分離したWindow UX preferenceとして扱う
- Glass削除時にstale preferenceをcleanupする

Tracking: PR #319

### V02-003 — Reachability / Snap Safety

Status: **MERGED**

Tracking: PR #321

- user drag後もGlassを完全にscreen外へ失わない
- multi-display切断時のrecovery contractを維持
- minimum visible areaを既存`DesktopGlassFrameCalculator`と整合させる
- Position Lock中でも明示的`Reset Glass Positions`はrescue操作として機能させる

## 4. Phase 2 — Glass Management UX

### V02-010 — General Source Reconnect

Status: **MERGED**

Tracking: PR #324 (format-only prerequisite), PR #325 (reconnect core + UI integration)

folder selection後にrestart-safe persistent identityをexact-matchし、live access / event subscription / initial snapshotを準備した上でstale configurationを再検証してconditional saveします。Unavailable Glassにはnative Reconnect controlを表示し、成功時は同じGlass ID / placementを維持したままruntime sessionを復旧します。core-only PR #323は#325へ統合してclose済みです。

v0.1ではrestartまたはGlass再作成が必要だったsource reconnectを、通常のGlass management UIから実行可能にします。

必須条件:

- saved security-scoped bookmarkをprimary referenceとして維持
- restart-safe persistent identityがある場合はexact-match validation
- stale UI stateをreconnect authorityにしない
- reconnectによってuser-owned fileを変更しない
- reconnect成功時にGlass ID / placement / window preferenceを維持する

### V02-011 — Connected Folder Actions

Status: **MERGED**

Tracking: PR #326

- connected folderをFinderで表示
- source availability / permission stateを明示
- destructive filesystem actionは追加しない

### V02-012 — Glass Rename

Status: **MERGED**

Tracking: PR #327

Glass表示名だけを変更します。source folder自体のrenameは行いません。

- title validationを既存Domain ruleと共有
- configuration optimistic concurrencyを維持
- folder path / bookmark / identityは変更しない

### V02-026 — Per-Glass File Sorting

Status: **MERGED**

- per-Glass UserDefaults persistence

### V02-027 — Folders First

Status: **MERGED**

Tracking: PR #338

- directoryだけを先頭groupへ寄せる
- package / alias / symbolic linkはdirectory扱いにしない

- per-Glass UserDefaults persistence
- FolderSnapshot / File Safety authorityは変更しない

### Additional candidates

- hidden-file visibility control（snapshot enumeration semantics変更が必要なためv0.2 core外）

Preferenceを追加する場合、次を区別します。

```text
Glass configuration authority
  -> source / placement / identity / durable Glass semantics

Window UX preference
  -> lock / visual presentation / transient macOS behavior
```

Window UX preferenceをFile Safetyやfolder identityのauthorityへ昇格させません。

## 6. Phase 4 — v0.2 Release Readiness

Tracking: PR #332

- `MARKETING_VERSION=0.2.0`
- `CURRENT_PROJECT_VERSION=3`
- public v0.1.1 build 2よりbuild番号を単調増加
- Release Candidate Validationでversion extraction / unsigned Release buildを検証

### V02-031 — Legacy Public Build History Compatibility

Status: **MERGED**

Tracking: PR #333

- v0.1.0 build 1 / v0.1.1 build 2をpublic distribution historyとして扱う
- pre-`RELEASE_EVIDENCE.txt` Releaseはpinned manifest + live target SHA + published BUILD_INFO SHA-256でexact validation
- normal production Releaseは従来どおり`RELEASE_EVIDENCE.txt`を優先
- unknown / modified / ambiguous legacy historyはfail-closed
- publication前と直前revalidationの両方で同じhistory materializerを使用

### V02-032 — Ad-Hoc Test Candidate

Status: **MERGED**

Tracking: PR #339

- current project versionからad-hoc signed Release candidateを生成
- Hardened Runtime / Sandbox / user-selected read-write entitlementをfinal bundleで再検証
- Developer ID authority混入を拒否
- SHA256SUMS / BUILD_INFOをActions artifactへ保存
- GitHub Releaseは作成しない
- production `RELEASE_EVIDENCE.txt`やnotarized candidateの代替にしない

### V02-034 — Ad-Hoc Candidate Source Binding

Status: **MERGED**

Tracking: PR #342

- manual ad-hoc candidateはexact `main`限定
- checkout `HEAD`と`GITHUB_SHA`のexact matchを必須化
- Pull Requestでは同じbuild/sign/verify pathを検証するがartifactはretentionしない
- Manual QA用download artifactとPR validation artifactを混同させない
- source guardのnegative fixtureでwrong branch / SHA mismatch / malformed SHA / unsupported eventを拒否

### V02-035 — Local Release Source Verification

Status: **MERGED**

Tracking: PR #343

- administrator helper実行前にlocal branchがexact `main`であることを確認
- clean working treeを必須化
- local HEADとlive GitHub main SHAのexact matchを必須化
- malformed / stale / detached / dirty / probe failureをfail-closed
- governance setup / read-only attestationの双方で先に実行

### V02-036 — Production Environment Source Binding

Status: **MERGED**

Tracking: PR #344

- `setup-production-release-environment.sh`のsetup / credential-name verification双方でexact live `main` source proofを必須化
- stale / dirty / detached / non-main checkoutからEnvironment mutationやcredential attestationを開始しない
- source verifier変更時にRelease Environment Setup Testsを必ず起動するtransitive path coverageを追加
- stale local HEAD fixtureでEnvironment PUT / POST前のfail-closedを固定

### V02-037 — Governance Helper Source Binding

Status: **PR OPEN**

- `setup-release-governance.sh`自身でexact live `main` source proofを必須化
- checked-in canonical ruleset recipe validationをremote probeより先に維持
- stale / dirty / detached / non-main checkoutからruleset / release-immutability mutationを開始しない
- verify-only administrator attestationもexact live `main` checkoutに限定
- source proof + final governance read-backのbranch probe順序をfixtureで固定

Operational blocker remains Issue #33:

- `main` protection / canonical ruleset
- repository release immutability
- `production-release` Environment credentials / protection
- real Developer ID signing + Apple notarization
- exact signed candidate Manual QA

Current signed/notarized candidate target is `0.2.0 / build 3`.

### V02-033 — Release Notes / QA Handoff

Status: **MERGED**

Tracking: PR #340

- READMEのv0.2 current stateをmain実装へ同期
- Draft Release Notesでuser-visible差分 / safety boundary / known limitationを整理
- ad-hoc candidateとDeveloper ID production candidateを明確に分離
- Manual QAの入口を固定

## 7. Deferred Beyond v0.2 Core

次はv0.2 coreへ混在させません。

- user-owned source Move
- user-owned source Rename
- user-owned source Delete
- recursive folder copy
- deep drop
- cloud backend
- runtime AI
- private macOS API

必要になった場合は個別ADR / Safety design / failure-path testsを先に作成します。

## 8. Quality Gates

- strict changed-file `swift-format`
- Swift Package tests
- AddressSanitizer
- Debug / Release app build
- macOS 15 compatibility build
- Architecture Guard
- File Safety Guard
- Public Repository Guard
- relevant visual snapshot / Manual QA
- new persisted stateがある場合はrestart / malformed state / cleanup tests
