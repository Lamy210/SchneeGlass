## 1. 目的と対象

Finderを開かず、任意の実フォルダの内容をデスクトップGlassから安全・快適に扱う、macOS 15以降の長時間常駐ネイティブアプリ。v1.0 は機能数ではなく、日常使用、復旧、互換性、実測性能、配布の検証可能性で判定する。

既存のnon-destructive契約を維持する。user-owned source Move/Rename/Delete、silent overwrite、unknown staging auto-delete、権限外mutationは0件。Finderがsource of truth。新規クラウド、Runtime AI、private API、Full Disk Access、Accessibility Permission、network entitlement、Developer ID/Apple notarization は対象外。既存Ad-hoc配布のGatekeeper制約を明示する。recursive folder copy、deep drop、plugin framework、自動更新、SQLite移行は別ADRと採否判断を要し、v1.0必須ではない。

## 4. v1.0 Definition of Done

- 既存File Safety/Architecture/Public Repo guards、変更Swift strict format、package tests、macOS 15 compatibility、canonical Debug/Release、関連Visual snapshots、ASan成功。TSan/CodeQLは対象HEADまたは同一候補の関連コードに対する実行証跡を確認し、未解決の重大指摘なし。
- 全P0/P1項目は完了または明示的な仕様縮小により受入条件を更新してレビュー済み。重大なデータ損失/破損・起動不能・復元不能・操作対象誤り・権限逸脱・配布物不整合は未解決0件。
- macOS 15/26の実機QAにてclean install、Gatekeeper、通常使用、sleep/wake、external drive、display切断、終了/再開、旧バージョンからのupgrade、Recovery。OS/build/architecture/commit/ZIP checksum/resultを記録。未検証architectureは対応と断言しない。
- 500-item snapshotは既存ceiling worst < 0.5sを維持（CI条件）。追加の性能目標は実測前の仮説: 8 Glass・各500 files、8時間常駐、sleep/wake 10回でcrash/hang 0・権限リーク0・idle CPU中央値1%以下・peak RSS/descriptor数を記録し、warmup以降の持続的増加を調査。端末/OS/測定条件を固定して閾値を見直す。共有runner値を実機SLOに転用しない。
- 配布はADR-0011を遵守。既存公開buildより単調増加、exact candidate provenanceと実機QAを結合、公開物のchecksumとread-back成功、既存Release/タグの上書きなし。更新失敗時は前版の案内と設定復旧手順（無条件downgrade保証ではない）。
- 新規SLO、対応OS/CPU、権限、配布方針の変更は別レビュー。QA未実行をPASSとしない。

監視はローカルログ/計測のみ。監査情報、絶対path、raw bookmarkを公開しない。バックアップは既存最大5世代のatomic JSONとRecoveryを利用し、破損時に勝手に上書きしない。クラウド運用費は追加しない前提。CI消費は重いbuild/実機QAをreleaseに集中し、既存required checksを省略しない。

## 6. 開発順序・運用

次の開発はまず#534/#535の最新HEAD確認と、#519の管理者作業の依頼。#520の残要件を細分化し、publisherを単独変更として設計/テスト。並行して既存UXと実機QAの差分を棚卸しし、U01から一つずつ進める。

既存docs/ADRが仕様の基準。OpenSpecは未導入のため本PRでは新しい依存/ルールを追加しない。導入する場合は既存規約と衝突しない最小PoCおよび個別提案（proposal/design/specs/tasks、既存ADRへの参照、仕様二重管理禁止）を先行し、既存Issue/PRを置き換えない。

各PRで現状・目的・範囲外・受入条件・検証・指摘の真偽・残存リスクを記録。コード変更では旧実装で失敗し新実装で成功する回帰テストを優先する。CIと実機QAの未完了、管理者権限不足、課金・資格情報、破壊的変更の場合は該当操作のみ保留する。

本計画は仕様提案であり、実装完了・v1.0公開・既存Issueのcloseを意味しない。
